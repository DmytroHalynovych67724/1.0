# Резервні копії NaShary

Запускайте команди з папки проєкту. Копії містять приватні дані акаунтів, повідомлень та замовлень. Папка `backups/`, файли SQLite та їхні маніфести виключені з Git. Скрипт не дозволяє створювати копію в папках сайту або збірки.

## Створення

```powershell
npm run db:backup
```

Використовуються ті самі налаштування `.env`, що й для сервера: за наявності `TURSO_DATABASE_URL` та `TURSO_AUTH_TOKEN` створюється узгоджений знімок Turso в транзакції читання. Інакше читається локальна база з `DB_PATH` або `data/db.sqlite`. Міграції та зміни робочих даних не запускаються. Секрети не записуються у звіт.

Команда повертає шлях до нового файлу `backups/nashary-<час>.sqlite`. Поруч створюється `.manifest.json`: дата, тип джерела, кількість рядків у таблицях та SHA-256. Перевіряються структура SQLite й зовнішні ключі. Існуючий файл не перезаписується.

## Перевірка й пробне відновлення

Підставте фактичний шлях із результату створення копії:

```powershell
npm run db:verify -- --file "backups/nashary-<час>.sqlite"
npm run db:restore -- --file "backups/nashary-<час>.sqlite" --output "backups/restore-check.sqlite"
```

Відновлення створює **новий файл**, звіряє його контрольну суму, кількість рядків, цілісність та зв’язки. Воно відмовиться перезаписувати наявний файл. Маніфест потрібний для обох команд; зберігайте його разом із копією.

Копія з Turso зберігає таблиці, індекси, представлення, тригери, лічильники AUTOINCREMENT, двійкові дані та 64-бітні цілі числа. Тригери не виконуються повторно під час перенесення рядків.

## Межі й фактична перевірка

25 листопада 2026 року створено копію робочої бази Turso та перевірено відновлення в окремий локальний файл: 26 таблиць, цілісність `ok`, порушень зовнішніх ключів немає. Тести додатково перевіряють SQLite, переносний експорт, точність двійкових та 64-бітних значень, тригери, лічильники, відмову від перезапису та виявлення пошкодження файлу.

Команда відновлення не замінює робочу базу Turso. Перехід на відновлену хмарну базу потребує окремого керованого імпорту й перевірки сервера. Регулярне створення копій, приватне зовнішнє сховище та політика зберігання ще не налаштовані. Наявна копія є знімком на момент створення, а не безперервною резервною копією.
