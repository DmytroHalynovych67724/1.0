# NaShary — roadmap розвитку

Оновлено: 15 липня 2026 року. Наступна робоча сесія: 16 липня 2026 року.

## Концепція

**NaShary** — маркетплейс нової та вживаної електроніки з акцентом на низькі ціни,
торг і локальні пропозиції. Назва передає ідею «майже задарма».

Основна мова — польська. Додаткові мови — українська й англійська.

## Пріоритет 1 — фундамент і новий образ

- [x] Провести повний аудит перекладів на всіх сторінках і в динамічних повідомленнях.
- [x] Прибрати залишки українського тексту з польської версії.
- [x] Перевірити польські терміни, placeholder, помилки й SEO-тексти.
- [x] Закріпити бренд **NaShary** у frontend, backend, документації та metadata.
- [x] Замінити палітру, логотип, favicon, hero-блок і стиль карток товарів.
- [x] Зберегти адаптивність для desktop, tablet і mobile.

## Пріоритет 2 — три ринки

- [x] Додати регіони: Польща, Україна, Європа.
- [x] Валюти за замовчуванням: PLN, UAH, EUR.
- [x] Зберігати регіон, валюту й доступність окремо для кожного оголошення.
- [ ] Показувати локальні ціни, міста, доставку, пропозиції та промокоди.
- [x] Додати перемикач регіону незалежно від перемикача мови.
- [ ] Продумати конвертацію валют: фіксовані demo-курси або зовнішній API пізніше.
- [x] Не змішувати товари різних регіонів без явного вибору користувача.

## Пріоритет 3 — покупки й продажі

- [x] Розширити checkout: контактні дані, адреса, доставка, коментар і підтвердження.
- [x] Додати статуси замовлення: нове, підтверджене, відправлене, доставлене, завершене,
  скасоване.
- [ ] Дати продавцю список замовлень, що містять його товари.
- [x] Додати історію змін статусу замовлення.
- [ ] Додати персональні та регіональні акційні пропозиції.
- [x] Реалізувати основу промокодів: відсоток/сума, строк дії, регіон і ліміт.
- [x] Перевіряти промокоди та рахувати знижку тільки на backend.
- [ ] Додати безпечне резервування залишку й обробку скасування.

## Пріоритет 4 — торг і спілкування

- [x] Додати чат між покупцем і продавцем для конкретного оголошення.
- [x] Перша версія: SQLite + REST + періодичне оновлення повідомлень.
- [x] Передбачити статус прочитання та список діалогів. Блокування і скарги — наступне розширення.
- [x] Не показувати особисті контакти публічно.
- [x] Додати торг: покупець пропонує ціну, продавець приймає, відхиляє або відповідає
  зустрічною пропозицією.
- [x] Прийнята ціна діє лише для конкретного покупця, має строк і використовується в checkout.

## Пріоритет 5 — довіра

- [ ] Додати профіль продавця з датою реєстрації, статистикою та оголошеннями.
- [x] Проста верифікація: ручне demo-схвалення адміністратором із чесним поясненням.
  ручне схвалення адміністратором.
- [x] Додати badge верифікації без неправдивих заяв про перевірку особи.
- [x] Дозволяти оцінку лише після завершеного замовлення.
- [x] Оцінка: 1–5 зірок, короткий відгук, середній бал і кількість оцінок.
- [ ] Передбачити скарги, приховування відгуку адміністратором і захист від дублювання.

## Пріоритет 6 — AI-помічник

- [x] Перша версія без платного API: простий локальний помічник за сценаріями.
- [x] Допомога з пошуком за категорією, станом і бюджетом.
- [x] Помічник не вигадує характеристики, ціни або гарантії та читає реальний каталог.
- [ ] Пізніше передбачити підключення реальної AI-моделі через окремий backend adapter.

## Пріоритет 7 — мініігри та винагороди

- [x] Додати 2 мініігри: колесо бонусів і tech-quiz.
- [x] Нагородою є персональний промокод, а не прямі гроші.
- [x] Обмеження: одна спроба на день, історія нагород, 7 днів дії промокоду.
- [x] Результат і видачу промокоду визначає backend.
- [x] Промокод прив’язаний до користувача та поточного регіону.

## Технічні задачі

- [x] Спроєктувати міграції SQLite для regions, conversations, messages,
  offers, reviews, verifications, promotions і promo_codes.
- [ ] Розширити ролі та перевірки власності без послаблення поточної безпеки.
- [x] Додати інтеграційні тести для регіонів, промокодів, чатів, торгу, довіри й ігор.
- [ ] Не використовувати робочу SQLite-базу в тестах.
- [x] Оновити seed-дані для всіх трьох регіонів.
- [x] Оновити README й API-документацію; дипломний опис доповнюватиметься перед захистом.

## Порядок наступної сесії

1. Аудит польського перекладу.
2. Узгодження нового візуального напряму та палітри.
3. Повний ребрендинг у NaShary.
4. Модель трьох регіонів і валют.
5. Чати та торг.
6. Покупки, промокоди й пропозиції.
7. Оцінки та верифікація.
8. AI-помічник.
9. Мініігри.

## Критерій готовності

Кожен етап завершується лише після lint, автоматичних тестів, перевірки API та
візуального перегляду польської, української й англійської версій на desktop/mobile.
