# NaShary: акаунти та каталог

## Ролі

| Роль | Доступ |
| --- | --- |
| Користувач | Власні дані, пароль, оголошення, покупки, чат, обране й збережені пошуки |
| Модератор | Усе користувацьке + каталог модерації, приховування/відновлення оголошень із причиною, розгляд скарг, журнал |
| Адміністратор | Усе модераторське + призначення модераторів, блокування/розблокування звичайних акаунтів |

Реєстрація не приймає роль від клієнта. Адміністратора створює конфігурація сервера через ADMIN_USERNAME та ADMIN_PASSWORD; публічної реєстрації адміністратора немає. Після призначення ролі користувач входить повторно.

## Демонстрація

1. Зареєструйте звичайний акаунт: ім’я, email, унікальний логін, пароль і підтвердження пароля.
2. У кабінеті відкрийте «Особисті дані», збережіть контакти. Вхід працює за логіном або email.
3. Додайте власний товар через «Продати»: назва, модель, фото, стан, ціна, регіон і характеристики.
4. Введіть точну модель смартфона в назву — через коротку паузу почнеться пошук. Або заповніть бренд/модель і натисніть «Завантажити дані моделі».
5. Якщо є кілька результатів або джерело не дає точного збігу, оберіть потрібну модель. Перевірте обсяг пам’яті, регіональні відмінності та комплектність. Ручні зміни параметрів не перезаписуються.
6. Адміністратор у «Модерація → Користувачі» призначає модератора з обов’язковою причиною.
7. Модератор приховує тестове оголошення. Воно зникає з публічного каталогу, а оформлення замовлення через API відхиляється. Власник бачить причину у своїх оголошеннях.
8. Після виправлення модератор відновлює видимість. Дії записуються в журнал.

Зміна пароля та вихід відкликають усі сеанси акаунта. Блокування також робить старі токени недійсними. Контактні дані не включаються в публічні картки товарів.

## Асортимент

Публічна вітрина показує власноруч додані позиції та чотири позначені демонстраційні смартфони: два для Польщі, по одному для України та Європи. Вони потрібні для вигляду, не є підтвердженими товарними залишками й не оформлюються як покупки.

Старий демокаталог збережений у базі. Повністю показати його можна лише явно встановивши DEMO_CATALOG_ENABLED=true для окремого тестового середовища. У звичайному режимі залиште false.

Статичні приклади завантажуються, поки безплатний API прокидається. Реєстрація, вхід, модерація й збереження товарів завжди потребують доступного сервера та постійної БД. Не використовуйте локальний SQLite на ефемерному Render-диску для постійних акаунтів: наявна конфігурація підтримує Turso.

## Межі

Email зберігається і слугує логіном. Надсилання листів, підтвердження пошти та відновлення забутого пароля не підключені; інтерфейс не імітує ці операції. Імпорт реальних товарів із чужого магазину не виконується.

Автозаповнення використовує локальні довідникові записи, Open Icecat і резервний пошук. Для доданих точних варіантів джерела: [Apple iPhone 15 Pro Max](https://support.apple.com/en-us/111828), [Samsung Galaxy S24 Ultra](https://api.samsungmobilepress.com/media-assets/galaxy-s24-ultra?tab=specs). Це шаблони технічних даних, а не оцінка стану конкретного вживаного пристрою.

Для iPhone 11 додано довідниковий профіль за [Apple](https://support.apple.com/en-us/111865), [апаратним розбором iFixit](https://www.ifixit.com/News/33016/iphone-11-teardown) та [оглядом із вимірюваннями Notebookcheck](https://www.notebookcheck.net/Apple-iPhone-11-Smartphone-Review-More-than-just-an-affordable-Apple-smartphone.435087.0.html). З назви моделі заповнюється 19 із 22 параметрів; колір, пам’ять і регіональну SIM-версію потрібно обрати для свого пристрою. Для повторного пошуку в уже заповненому оголошенні можна явно увімкнути заміну поточних технічних даних. Стан батареї, дефекти й комплектність залишаються відповідальністю продавця.

«Роль і доступ» у кабінеті показує поточні права. Пряме відкриття вкладки модерації звичайним користувачем тепер показує пояснення, а не порожню сторінку. Це не дає права самостійно підвищити роль.

## Перевірки

### Нова техніка та дозволи продавців

Нові товари додає адміністратор магазину або продавець з окремим дозволом `canSellNew`.
Це не четверта роль і не права модератора. Б/в оголошення доступні всім активним акаунтам.
У кабінеті адміністратора: «Модерація → Користувачі → Дозволити продаж нової техніки».
Для видачі й відкликання потрібна причина; дія зберігається в журналі.
Після зміни дозволу продавець входить повторно. Відкликання ховає його нові товари з
публічного каталогу та зупиняє їх купівлю, зберігаючи оголошення в базі й кабінеті.

У формі нового товару є «Версія та постачання»: ринок, прошивка, мови, мережі,
комплектація, умови гарантії, артикул, код партії та термін постачання.
Ці поля описують конкретну поставку; автоматичне визначення моделі їх не змінює.
Для товарів «Під замовлення», «Очікується» та «Немає в наявності» кошик недоступний.
Уточнення постачання відбувається через повідомлення продавцю. Платні передзамовлення не реалізовані.
Існуючі товари без цих даних зберігають поведінку за фактичним залишком.

Код партії — текстова довідка. Повноцінні складські партії, унікальні SKU та імпорт
залишаються наступним окремим етапом.

Запустіть npm run check. API-тести використовують тимчасову БД і перевіряють авторизацію, email, зміну пароля, права трьох ролей, блокування, модерацію та неможливість купити приклади.
